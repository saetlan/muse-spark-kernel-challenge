waiting on the okc queue with nothing left to verify locally. Then: claim the highest unclaimed
item (small edit: your session name + UTC time in "Claimed by"), one item at a time; a claim with
no update for 2 h expires; if the owner is actively on it, take the next item.
**Code** goes in `shared/<item>/`, never in the owner's folder. **Judge time:** test it inside your
own problem if that problem contains the block (decode_layer has ①②③④, prefill has ①②③),
otherwise hand a locally verified lab section to the owner for its next lab check (owner's budget).
**Handoff:** message the owner session (path, what you verified, expected gain); the owner decides
and updates its "Shared building blocks" row; consumers embed only owner-judged files. Spending
rules are unchanged (rule 1).

## Pre-submission checklist (run before every `okc check` or `okc submit`)

Built from reading the judge's exact versions: Triton 3.8.0 and PyTorch 2.14.1 source, the PTX ISA (F24–F31).

1. **One command:** `sh moe/local/presubmit.sh <files>`. It runs the lint (`moe/local/lint_submission.py`), `py_compile` and the local CPU checks, including `check_v1_vs_baseline.py`: v1's `prepare`/`kernel_fn` must call SGLang's ops exactly as `baseline.py` does, apart from the intended changes (E0c). Nothing goes out unless it passes. When a version changes more of SGLang's path, widen that check's allowed differences on purpose, never by loosening it.
2. **Triton kernels:**
   - Read no plain module globals. Allowed: modules, other `@triton.jit` functions, `tl.*`, dtypes, and values made as `x = tl.constexpr(...)`. An annotation like `x: tl.constexpr = ...` is NOT allowed (F24).
   - Inline-asm strings: inline literals or `tl.constexpr`.
   - Outputs narrower than 32 bits are packed per register, and each thread's element count must be a multiple of `pack` (F25).
   - Triton builds for `sm_90a` on the H200, so Hopper-only PTX is fine (F26).
3. **`load_inline` CUDA:**
   - Pass `-gencode=arch=compute_90a,code=sm_90a` in `extra_cuda_cflags`. Any flag containing "arch" stops PyTorch adding its own, and its default is plain `sm_90`, which lacks wgmma (F27).
   - Launch every kernel on `at::cuda::getCurrentCUDAStream()`, never the default stream (F28).
   - Declare functions in `cpp_sources` and list them in `functions`.
   - Never set `TORCH_CUDA_ARCH_LIST` or any other `os.environ` entry.
   - nvcc time counts toward the run's 15-minute limit (TASK.md) and `prepare()`'s 300 s.
   - PyTorch compiles `.cu` sources with `-D__CUDA_NO_HALF_OPERATORS__ -D__CUDA_NO_HALF_CONVERSIONS__ -D__CUDA_NO_BFLOAT16_CONVERSIONS__ -D__CUDA_NO_HALF2_OPERATORS__ --expt-relaxed-constexpr`, and C++20 unless a `-std=` is given. So `a * b` or implicit float conversions on `__nv_bfloat16`/`__half` don't compile: use intrinsics (`__hmul2`, `__float2bfloat16_rn`, …) (F33).
   - `use_pch=True` precompiles `torch/extension.h`, and `no_implicit_headers=True` skips the prepended headers; both can cut compile time (F33).
4. **CUDA graphs:**
   - No host syncs, and no allocations or branches that depend on input values.
   - Every routing-dependent quantity (expert counts, token lists, tile schedules) stays on the GPU; host values computed at capture go stale on replay.
   - Grids are frozen at capture, so size them for the worst case and exit early.
   - Never cache anything keyed by `data_ptr`, `id`, contents or shape of the inputs. Replays reuse buffers, and the allocator reuses addresses.
   - Return a plain `torch.Tensor` and never touch it after `kernel_fn` returns (R-G).
   - Build TMA descriptors and other host-side setup in `prepare()`.
   - Put any build or cache directory under `/tmp` (`tempfile`); a sandbox may make the rest read-only. Triton's cache worked in E1.
   - CuTe DSL may recompile in every process, so budget its compile time (R-G).
   - Launch every Triton and CUDA kernel once in `prepare()`, so no first launch (compile and module load) lands inside a capture. Default capture mode "global" raises on unsafe calls (F29).
5. **Numerics:**
   - Decode with explicit PTX `mul.rn.bf16x2`. BF16 PTX math always keeps subnormals (it has no `.ftz`), and it needs `sm_90+` (F30).
   - Don't rely on Triton's own FP32 ops or libdevice math (`enable_reflect_ftz=True`) to keep subnormals (F31).
6. **The judge's static checks:**
   - Nothing that patches timing, reads frames (`inspect`, `sys._getframe`), touches harness I/O or secrets, edits loaded modules, imports `reference`/`checks`, starts processes (other than `load_inline`) or uses the network.
   - No `open()` on arbitrary files and no encoded or compressed source. The lint flags these.
7. **TMA (CUDA routes):**
   - Global address 16-byte aligned; strides multiples of 16 bytes; box dims ≤ 256.
   - Inner box bytes a multiple of 16 and within the swizzle span (128 B).
   - Tensor map 64-byte aligned.
   - Load FP4 as UINT8: the packed 4-bit TMA types are probably Blackwell-only (unverified) (R-T-B3).
8. **PDL:**
   - The consumer must `griddepcontrol.wait` before reading the producer's outputs and before overwriting buffers it may still read.
   - The producer triggers only after its writes are done. A trigger doesn't make data visible; TensorRT-LLM had a bug from triggering too early (R-T-B2).
9. **4-bit layout tests must cover the full K (4096), not one tile.** A wrong interleave can pass at K ≤ 128 and diverge beyond it (R-T-B1). Our CPU and lab tests compare full rows. They must also cover **every E4M3 scale** (0x00–0x7E, subnormals included): `nvfp4.random_weights` clamps scales to [8, 448] (F35), so use `_all_e4m3_scales` from `moe/lab/e1b.py`.
10. **Serving patches (from Nov 5):**
    - Outputs must agree with stock "nearly as well as stock agrees with itself", and batch shape alone changes numerics. Test every changed kernel or reduction order against stock at every concurrency, and keep reduction dtypes and order around the post-expert norm as stock has them.
    - Apply the top-k weights exactly once.
    - Profiling-only switches (balanced routers, routing simulation) give wrong outputs; never leave them on (R-S, R-T).
11. **Lab code:**
   - Only in check runs, generated by `moe/local/make_lab.py` so the timed code is the submission byte for byte.
   - Every section is time-boxed and wrapped.
   - Scored runs use the clean `submission.py`.
   - Locate packages with `importlib.util.find_spec(...).submodule_search_locations`, not by importing them: it runs no package code, and namespace packages have `__file__ = None`.
   - Nothing in a lab section may risk an out-of-bounds access: a CUDA fault is sticky, so the `try/except` can't contain it and the whole run fails.
